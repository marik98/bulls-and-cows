# Дизайн проекта Bulls and Cows

## 1. Структуры данных и алгоритмы

### Состояние игры и история попыток
Состояние игры (`GameState`) и история попыток (`Attempt[]`) хранятся в памяти в виде неизменяемых (иммутабельных) объектов. 
Для истории попыток используется массив. Это наиболее оптимальная структура, так как нам нужно последовательно добавлять новые записи и затем выводить их в том же порядке.
При добавлении новой попытки (функция `addAttempt` в `src/state.ts`) мы не мутируем старый массив (никаких `push`), а создаем новый через спред-оператор: `history: [...state.history, attempt]`. Это гарантирует предсказуемость состояния (иммутабельность) и упрощает отладку.

### Алгоритм `evaluateGuess`
Функция (`src/core/game.ts`) сравнивает строку секрета и строку догадки.
1. Строки приводятся к нижнему регистру и разбиваются на массивы символов.
2. С помощью метода `map` мы создаем массив объектов, где для каждого символа догадки находим его индекс в секрете (если он там есть).
3. С помощью метода `filter` мы сначала отбираем «Быков» (символы, чей индекс в секрете совпал с индексом в догадке).
4. Затем вторым `filter` отбираем «Коров» (символы, которые есть в секрете, но их индексы не совпадают).
Ручные циклы со счетчиками не используются (требование задания).

### Алгоритм `countPossibleSecrets`
Функция (`src/core/game.ts`) считает количество возможных уникальных секретов по формуле перестановок без повторений: P(base, length) = base! / (base - length)!.
Реализована через рекурсию: `base * countPossibleSecrets(length - 1, base - 1)`.
Для оптимизации (мемоизации) используется `Map`. Перед началом вычислений функция проверяет, есть ли результат для текущих `length` и `base` в кеше (`memoCache`). Если есть — возвращает мгновенно, избегая повторных вычислений.

## 2. Сложность (Big O)

*   **`generateSecret`** — Время: **O(n * m)**, где n — длина секрета, m — размер алфавита (система счисления). Внутри используется `reduce`, который на каждой итерации фильтрует пул доступных символов (`filter`). Память: **O(m)**, так как мы храним пул символов.
*   **`evaluateGuess`** — Время: **O(n^2)**, где n — длина секрета. Метод `map` проходит по всем символам догадки (O(n)), и внутри для каждого символа вызывается `indexOf` по массиву секрета (в худшем случае O(n)). Память: **O(n)** для хранения промежуточного массива `matches`.
*   **`isValidGuess`** — Время: **O(n)**, где n — длина догадки. Мы проходим по строке один раз для проверки валидности символов (`every`) и один раз для проверки уникальности (`new Set`). Память: **O(n)** для хранения массива символов и Set.
*   **`countPossibleSecrets`** — Время: **O(n)** благодаря мемоизации, где n — длина секрета. Без мемоизации было бы O(n!), но `Map` кеширует результаты, и рекурсия выполняется только для новых значений. Память: **O(n)** для хранения стека вызовов и кеша.

## 3. Принципы чистого кода

*   **Чистые функции (Pure Functions)**: Вся игровая логика (`src/core/game.ts`, `src/core/validators.ts`) не зависит от DOM и внешнего состояния. Они возвращают новые значения на основе входных данных и не вызывают побочных эффектов. Например, `evaluateGuess` детерминирована (при одинаковых аргументах всегда один результат).
*   **Иммутабельность (Immutability)**: Функции обновления состояния (`addAttempt`, `setWinStatus` в `src/state.ts`) не изменяют переданный объект `state`, а возвращают новый объект с обновленными полями.
*   **Функции высшего порядка (HOF)**: В `evaluateGuess` активно используются `map` и `filter`. В `generateSecret` — `reduce` и `filter`. В `isValidGuess` — `every`.
*   **Каррирование (Currying)**: Функция `createDigitValidator` (`src/core/validators.ts`) принимает систему счисления и возвращает функцию-предикат. Это позволяет переиспользовать её как для валидации в логике, так и для фильтрации ввода в UI (`src/main.ts`).
*   **Мемоизация (Memoization)**: Реализована в `countPossibleSecrets` через `Map` для кеширования результатов рекурсивных вызовов.
*   **Разделение ответственности (Separation of Concerns)**: UI-слой (`src/main.ts`) полностью отделен от игровой логики (`src/core/`). UI только вызывает чистые функции и отрисовывает результат.
